Use the `paocli` family when you want an interactive exploit driver that stays attached to a specific debug session.

## `paocli`

`paocli` writes the provided script into the session runtime directory, launches it with `uv run`, and exposes both startup output and any parsed attach result marker.

```json
{"tool":"paocli","arguments":{"session_id":"chal-a","binary_path":"/workspace/chal","file":"from pwn import *\nprint('ready')\n"}}
```

### Important returned fields

- `runtime_dir`: session-specific directory used for the inline script
- `io.current_output`: output collected for this call
- `attachment.result`: parsed attach result marker when present
- `startup.ready`: whether the driver reached a ready state
- `startup.reason`: why the wait finished
- `startup.alive`: whether the driver is still alive
- `startup.pid`: driver process id
- `startup.replaced`: whether an older driver was replaced for this session

## I/O tools

```json
{"tool":"sendinput","arguments":{"session_id":"chal-a","data":"AAAA\n"}}
{"tool":"checkoutput","arguments":{"session_id":"chal-a"}}
{"tool":"checkevents","arguments":{"session_id":"chal-a"}}
```

- `sendinput` writes raw bytes to stdin
- `checkoutput` returns buffered output and clears it
- `checkevents` returns structured events plus `alive`, `exit_code`, and `driver_pid`

<Warning>
  `sendinput` does not append a newline automatically.
</Warning>

## Session management tools

```json
{"tool":"paocli_stop","arguments":{"session_id":"chal-a"}}
{"tool":"list_paocli_sessions","arguments":{}}
```

- `paocli_stop` kills the driver bound to a session
- `list_paocli_sessions` lists all active drivers

## Research evidence fuse

```json
{"tool":"paocli_link_evidence","arguments":{"session_id":"chal-a","research_session_id":"case-1","label":"heap-spray","max_chars":8000}}
```

- drains pipe output + structured events without killing the driver
- stores a capped research note (`max_chars` 1–32768) and links a
  `tool_result` evidence entry (`paocli:<session_id>`)
- response carries `output_truncated` plus `pipe_stats` (queued/dropped
  bytes and events, malformed control-line count) so a capped note is
  never mistaken for complete output

## Behavior notes

- one `paocli` driver per debug session
- launching a new driver for the same session replaces the old one
- `close_debug_session` also stops the session's active driver
