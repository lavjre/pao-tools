These tools are for helper services, build steps, and supporting automation. They are not for running the target binary under debugger control.

<Warning>
  `run_command` and `spawn_process` intentionally guard against some bad patterns, including using them to run a target ELF from `/workspace` or wrapping `python -c` instead of using the Python tool family.
</Warning>

## Returned shape

All tools on this page return the shared structured [Response API](/concepts/response-shapes).
Stdout and stderr are drained through bounded pipes rather than written directly by
the child. Their combined storage has a hard per-process limit. Within that limit,
large streams are spooled to disk and their fields contain an artifact descriptor
instead of an oversized inline string.

The default combined limit is 256 MiB and is configurable with
`PAO_MAX_PROCESS_OUTPUT_BYTES`. When a process emits one byte beyond the limit,
pao-tools stores exactly the allowed prefix, discards only bytes already observed
beyond it, kills the complete process tree, and returns:

- `success: false`
- `code: "RESOURCE_EXHAUSTED"`
- `type: "ProcessOutputLimitError"`
- `output_limit` with exact per-stream and combined `observed_bytes`, `stored_bytes`,
  and `dropped_bytes`

`measurement_complete` tells callers whether both pipes reached EOF. Output loss is
therefore explicit; the API never presents a quota-limited result as complete.

## `run_command`

Use for short-lived shell commands such as compiles and helper scripts.

```json
{"tool":"run_command","arguments":{"command":"gcc -g vuln.c -o chal","cwd":"/workspace","timeout":30.0}}
```

Large-output response excerpt:

```json
{
  "data": {
    "command": "objdump -d /workspace/large-chal",
    "returncode": 0,
    "stdout": {
      "delivery": "artifact",
      "artifact_id": "4d3d4d939ae047a1a90a0ffda031bcd2",
      "tool": "run_command",
      "content_type": "text/plain",
      "encoding": "utf-8",
      "size_bytes": 7340032,
      "sha256": "...",
      "stream": "stdout"
    },
    "stderr": "",
    "cwd": "/workspace"
  }
}
```

Read the output with [artifact tools](/tool-reference/artifacts). The original bytes
stored within the process budget are available through `content_base64`, including
chunks that split a UTF-8 character.

## Background helpers

| Tool | Use it for | Important fields |
| --- | --- | --- |
| `spawn_process` | start a long-running helper process | `pid`, `stdout_path`, `stderr_path`, `process_dir` |
| `get_process` | inspect one tracked background process | running status plus live or final output |
| `kill_process` | stop a tracked process tree | signal defaults to `15`; unmanaged PIDs are rejected |
| `list_processes` | inspect all tracked helpers | lightweight running-process summary |

```json
{"tool":"spawn_process","arguments":{"command":"python3 -m http.server 8000","cwd":"/workspace"}}
{"tool":"get_process","arguments":{"pid":12345}}
{"tool":"kill_process","arguments":{"pid":12345,"signal":15}}
{"tool":"list_processes","arguments":{}}
```

## What gets tracked

- stdout and stderr are written to log files under a server-managed process directory
- `get_process` returns live output for tracked running processes when available
- `list_processes` reports the per-process output budget in `capacity` and retains a
  bounded summary for recently terminated helpers
- when `get_process` or `kill_process` collects a terminal process, final output is
  returned inline or persisted as an artifact, then its temporary log directory is
  removed
- closing a debug session stops every managed helper process owned by that session;
  its response reports cleanup and failure counts

The paths returned by `spawn_process` are live-tail paths only while the process is
running. Terminal responses set those paths to `null` after lossless output delivery.
Only the prefix covered by `output_limit.limit_bytes` is lossless after a quota error;
the response accounts for every additional byte drained before termination.
